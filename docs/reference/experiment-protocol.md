# FocOS 性能实验与图表要求

当前无文件系统或向量检索的实测数据。本文件定义将要执行的实验，不预设加速倍数。每个结论必须同时说明条件、成本、失败或无收益的情况。

## 基线与消融

先冻结通过功能/错误测试的简单 FAT32 写穿实现 B0，配齐 I/O 计数。B1 为同预算普通块缓存 + 写穿，是后续策略的工程对照；仅和完全无缓存比较不足以说明新策略的价值。

以 B1 为共同基础，独立测试目录缓存 D、写回 W、D+W；对最终方案逐项关闭，保持总内存预算、数据布局和请求序列不变。W 依赖块缓存，不构造不可能的「无块缓存但有写回」组合。若轨迹显示 FAT 簇链定位才是瓶颈，则增加簇链缓存 C 的独立开关和实验，不把它与目录缓存混为一项。

优化开关应改变策略而不改变应用正确性、数据量、准确率或持久化要求。采用稳定提交加参数运行；涉及不同提交时同时记录基线与实验 SHA。向上层报告成功前的语义不能随性能模式偷偷改变。

## 工作负载和解释链

| 负载 | 目的 | 必须测量 |
| --- | --- | --- |
| 顺序读写 | 检查优化是否损伤简单负载，观察带宽上限 | MiB/s、CPU 占用、物理请求数、缓存占用 |
| 4 KiB 随机读 | 块缓存的局部性收益与随机失效边界 | IOPS、p50/p95/p99、命中率、数据/元数据读请求 |
| 热点读与均匀随机读 | 区分热点重用和工作集超过缓存的行为 | 相同请求序列下不同缓存容量曲线、逐出次数 |
| 多目录 lookup/open/stat | 验证目录缓存及失效正确性 | 查找耗时、实际目录块读数、创建/删除后可见性 |
| 碎片化大文件随机定位 | 定位 FAT 链遍历成本 | FAT 访问数、CPU 时间、簇链缓存占用 |
| 小块覆盖写与混合读写 | 验证写合并、写回与读写一致性 | 写放大、dirty 峰值、flush 延迟、完成全部同步的总时间 |
| 用户态磁盘向量检索 | 验证应用收益 | Recall@k、QPS、查询 p95、I/O 次数/字节、CPU 与等待时间、总内存 |

读取同一已打开索引文件的查询不会反复走路径查找，不能用这种负载证明目录缓存有效。只读查询也不能证明写回收益；写回须用真正的更新/导入或独立写负载验证。每个优化都有对应的负载和无需产生收益的对照组。

## 写回的正确性与计时边界

分别报告写入调用返回时间、显式 sync/flush 时间、从开始到全部要求的持久化完成的总时间。固定 dirty 上限、逐出策略、错误传播和回压规则。不能只测复制进缓存的速度。

成功 sync 后关闭/重启并校验内容，注入块写失败验证错误不会被吞掉，写回失败的脏块不能被无条件释放。设备不支持有效 flush 时标注只能完成到哪个层次，不能称为断电持久化。FAT32 无日志的实现不据此宣称任意断电原子性；数据、FAT 与目录项更新顺序及中断写入后果需单独设计和测试。

## 向量检索的实施方式

先在 host 上确定性构建图索引并生成精确近邻 ground truth，再冻结图、向量、查询集和校验和。内核中的用户程序运行查询，图节点/向量按需从 FAT32 文件经 syscall 读取。明确这是磁盘承载的 HNSW 风格查询实现，不能把一次装入全部索引后的纯内存 HNSW 计为随机磁盘 I/O 证据。

建议先做只读查询，不在区域赛同时实现在线建图、向量数据库协议或网络服务。记录 N、维度、距离函数、M、efConstruction、efSearch、k、查询数与随机种子；内存预算包含应用缓存、索引常驻部分、文件缓存、元数据及临时空间，工作集至少覆盖小于/等于/大于缓存的情形。

在同一索引和查询参数下校验结果与 Recall@k，再比较速度；如需比较不同参数，使用同一召回率目标。图搜索本身的距离计算可能是主要开销，因此同时测 CPU 时间和 I/O 等待比例，解释为什么某种文件系统优化有收益或没有收益。

先用均匀/热点随机读搭出可重复工具，再接入真实公开向量数据和真实查询，不把随机读微基准标成完整向量检索。HNSW 算法背景见 [原始论文](https://arxiv.org/abs/1603.09320)。

## 每次运行必须保存的条件

记录 run ID、UTC 时间、内核及测试仓库完整 SHA、Rust/链接器/构建参数、板型号与修订、固件、CPU 频率/核数、内存限制、介质型号/容量、控制器模式、分区与 FAT32 簇大小、镜像与数据哈希、缓存总预算及各策略分配、dirty 上限、并发度、请求大小、随机种子、预热方式、清缓存方法、flush 计时边界、每轮结果和失败状态。

“冷”应注明清除的是应用缓存、内核缓存、设备缓存还是全部可控层；清空 OS 缓存不等于清空存储控制器缓存。每轮恢复同一初始镜像或可证明相同的状态，写测试不能逐轮改变碎片与空闲布局而不记录。

每个配置至少 7 轮独立运行，交错或随机化基线/优化顺序；报告中位数和 IQR，若给置信区间须说明方法。尾延迟每轮应有足够查询样本，建议至少 1000 次；独立轮次是重复实验单位，不能把同一轮相关请求伪装成大量独立实验。计时区间内关闭逐请求 UART 打印，统计集中输出。

QEMU 用于功能与实验工具回归；核心硬件性能结论来自真实板。跨平台分别在同一平台上做 B0/B1/候选方案比较，再展示相对收益。VisionFive2 的 SD 卡与星云板 SSD 的绝对速度差不能归因于 CPU 架构或 HAL 优劣。

## 答辩图表清单

| 图表 | 直接回答的问题 |
| --- | --- |
| 功能 × 测试集 × 环境热力图 | 基本功能在哪些条件下得到验证，哪些还缺失？ |
| 延迟分布/CDF 与吞吐 | 典型操作和尾延迟改善了多少？ |
| 数据/元数据 I/O 数与命中率 | 加速来自少读了哪些块？ |
| 固定预算下的策略消融 | 每项策略贡献多少，是否相互依赖？ |
| 缓存容量/工作集曲线 | 收益何时出现、何时消失，内存成本多少？ |
| 写入返回/flush/总持久化时间 | 写回是否只是推迟了工作？ |
| 双平台各自归一化收益 | 相同实现是否在两板保持效果？ |
| Recall@k—QPS/延迟与每查询 I/O | 应用在保持结果质量时是否受益？ |
