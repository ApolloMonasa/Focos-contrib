# TEST-001：先记录真实调用，再解释测试结果

本页重新确定采集、调用状态和判分之间的边界，供独立 SPEC PR 审阅。依据是[12 组输出复查](test001-benchmark-output-audit.md)及[本地隔离实验](../../tests/test001/fixtures/isolated-pilot/README.md)。旧实现和旧 SPEC 提供问题线索，不作为正确性依据；已核实的镜像身份、原始样本和评审反例继续保留。

## 要改变什么

采集器回答“执行了哪个调用，收到了哪些字节，怎样结束，环境是否清理”；组解析器回答“这些字节对该程序意味着什么”；验收器再判断证据是否足够。任何一层都不能用包装器的 success/END/退出 0 替其他层补证据。

```text
经审定调用计划 → 独占输入快照 → 隔离执行单元
                              ↓
                   调度记录 + 原始输出 + 主机状态
                              ↓
                传输校验 → 按调用归属 → 组语法解析
                              ↓
                原生结果/指标 → 判据 → 验收报告
```

这是一条解析与判分路径。原始输出中的控制文字仍是输出，不能反过来创建调用身份、修改主机状态或宣布清理完成。

## 调用计划和隔离边界

PROFILE 必须区分三个对象：`invocation_id` 是实际调用，`coverage_id` 是待覆盖项目，`isolation_unit_id` 是共享同一次来宾环境的有序调用集合。三者显式映射，不把 judge 键当作进程，也不把一个 LTP 程序打印的多条 TPASS 当作多次调用。

- 首个正式参考 Linux 后端采用“一隔离单元一全新来宾”，结束后销毁整个来宾。可独立的 Lua/libc-test 调用分别隔离；BusyBox 文件操作链等共享状态调用必须整链纳入一个单元，不能盲目拆开。
- 同一单元内的执行顺序、共享文件、后台服务、工作目录和清理动作提前登记。没有依赖证明时，不把失败后的后续调用当作独立有效运行。
- 新调度器必须逐调用收集状态。继续调用未经改造的组脚本只能取得组级事实；原脚本没有输出的子调用状态必须标为未知，不能凭管道末端或最后 echo 补出。
- ELF、浮点 ABI、解释器和库分别绑定；目录标签只是计划中的槽位名。显式 shell、加载器别名和网络/用户/文件准备写入 PROFILE。环境适配不是测试结果修复，也不自动证明两套 libc 覆盖成立。
- 批次仍每个冻结槽位只尝试一次。一个槽位可含多个预先登记的隔离单元，单元并集必须恰好覆盖槽位清单；不得运行后只选择成功单元。增加隔离单元要求新 PROFILE revision；包格式升为 v3，具体单元布局及摘要规则见[阶段契约](test001-redesign.md#文件与发布契约)，旧包不能补造这些记录。

## 采集必须留下的事实

以下是正式采集的必需字段；具体编码与传输限额在 B/C 子规格中审定后才能实现，不把本地 pilot 的字符串标记直接升格为生产协议。

| 记录 | 必需内容 | 缺失或矛盾时 |
| --- | --- | --- |
| 单元启动 | 运行/槽位/隔离单元 ID、计划哈希、输入与实现身份、实际环境 | 不能证明来源，验收 BLOCKED |
| 前置动作 | 动作 ID、结果、依赖关系 | 失败的依赖调用 NOT_RUN，不继续执行并伪造正常结果 |
| 调用启动 | invocation_id、实际 argv/cwd/env、子进程身份、单元内序号 | 不能按输出名称或到达顺序猜身份 |
| 输出块 | invocation_id、stdout/stderr、各流连续序号、原字节、接收位置 | 重复、丢块、未知调用或越界阻断；跨流不虚构写入总顺序 |
| 调用终结 | 启动失败/退出/信号/超时分别记录；原生 wait 状态、收集完整性 | shell 的 137 不能自行解释成确定信号；成功文字不补终结 |
| 清理 | 已登记后台任务、剩余进程检查、回收结果和单元销毁 | 留下后代、未知或未确认清理均阻断 |
| 主机终结 | QEMU 原始退出状态、独立超时/超限原因、主机进程组回收、已保存日志范围 | kill 后的负退出码不覆盖 TIMEOUT；回收失败不启动下一单元 |

调度记录与被测 stdout/stderr 分开采集。即使共用物理串口，输出必须由监督进程编码为带调用身份的数据块，不能把原生文本直接当调度命令；控制帧、数据块、截断和长度错误有独立校验。各流原字节保留，不删颜色、不合并行后重建证据。直接写控制台的程序需单独登记输出来源；无法归属的旁路数据阻断，不能假定所有程序都只写继承的 stdout/stderr。这里防止日志误归属，不建立对恶意内核或 root 程序的安全认证。

正式采集必须边执行边保存输出。超时后已收到的前缀仍可追溯，未收到的尾部明确不完整。本地 pilot 将 stdout/stderr 暂存在来宾文件、结束后再编码导出，所以超时会丢失这两个文件；它验证状态阻断和来宾销毁，不满足此项正式要求。后续实现须用“输出前缀后挂起”的用例验证实时采集，不能以本实验代替。

## 原生结果与最终验收

1. 传输校验只建立可信的调用边界和原字节归属，不识别 Pass!/TPASS 或性能含义。
2. 组解析器按经审定的生产者语法处理调用内容，保留诊断、原生结果、指标和错误；不读整份其他调用日志补成功，不依赖 RESERVED 识别任意其他组输出。
3. CRITERIA 定义原生状态与输出的联合判据。固定 libc-test 的 `Pass! + 运行器退出 1` 可满足局部成功条件，`FAIL + 退出 1` 必须失败；单独的 1 两者都不能推出。Lua 包装器退出 0 也可伴随 fail。启动失败、信号、超时、缺结果、矛盾输出不能放行。
4. 指标的原值、原标签、来源、公式和维度分开。UnixBench 的单位冲突未解决前只保留观察，不发布规范性能值。改变脚本换算或运行参数必须重新审阅，不能事后静默纠正原始数值。
5. 验收只消费上述单一分析结果，仍要求可信运行包、完整覆盖、正确顺序、所有联合判据合格及清理完成。参考 Linux 局部结果和本地 pilot 不计 FocOS/VF2 成绩；pilot 的 acceptance 始终 BLOCKED。

旧外部日志没有新调度记录时，继续遵守外部日志入口和已审语法约束。它不能补造进程状态、输出流身份或清理证明；新记录也不能绕过既有原始 UTF-8 校验与错误保留规则。

## 实现次序和合并门槛

| 顺序 | 交付 | 合并前必须看到 |
| --- | --- | --- |
| 现在 | 本 SPEC、全组差异和受限隔离实验 | 来源、反例、设计边界及缺口清楚；一名非作者批准。实验不注册生产入口 |
| 1 | Lua 与 libc-test 小范围 A0/A1/A2 | 各自完整语法与原生状态映射；真实正反例；已存在 Lua 错误不能回归；外部日志不能验收通过 |
| 2 | 同一范围 B/C 的包与采集子规格，再实现 | 先审定实时传输编码/容量、原生 wait 状态与隔离单元清单；私有输入、半写发布、输出前缀超时、后代回收及新运行包验收均有实际证据 |
| 3 | A3 逐组扩展，B/C 同步新增依赖和采集能力 | 每组完成语法、指标计算、环境、正反例及顺序/清理；不因另一组通过而放行 |
| 4 | D 完整批次 | 所有冻结槽位/单元完整覆盖，所有失败留存，无挑选成功重跑；之后另做 FocOS/真板验收 |

这调整的是交付依赖顺序：不再等全部组解析完才首次验证采集链，也不提前宣布完整 A/B/C 已完成。生产 CLI 名称与外部日志限制不变。#56 保持 Draft，设计通过后重新核对其 Lua 范围；值得保留的模块须带已有反例迁移，不能因之前通过评审而豁免。libc-test 和新采集协议另开实现 PR，不继续堆入 #56。

本次允许合并的是已经由证据支持的职责、状态和判据边界；完整 LTP、原环境全组成功样本、实时传输编码和生产实现仍有明确后续门槛。不能把这些未完成项标为已冻结或已经验证。
