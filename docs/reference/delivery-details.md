# 实现时查：模块边界

区域赛范围见 [REGION-001](../../specs/REGION-001.md)，日期和风险见 [路线](../roadmap.md)。此页只回答接口怎么分。CPU、板型和驱动的依赖关系见 [架构](../architecture.md)。

| 模块 | SPEC 先约定什么 | 不能泄漏什么 |
| --- | --- | --- |
| BlockDevice | 扇区大小/数量、越界、超时、读写完成与 flush 能力 | MMIO、DMA、控制器细节不进 FS |
| 架构层 / HAL 接口 | [ARCH-001](../../specs/ARCH-001.md)：页表权限、TLB、异常/上下文、CPU 时钟与 ABI | PTE/CSR 不进入公共策略 |
| 板级层 | [PLAT-001](../../specs/PLAT-001.md)：启动资源、内存保留区、设备连接与初始化顺序 | 板名、地址、频率不进公共内核 |
| 驱动层 | [DRV-001](../../specs/DRV-001.md)：控制器、DMA/IRQ、完成/错误与资源释放 | 控制器寄存器不进 FS/VFS |
| 内存 | 页与堆所有权、OOM、用户复制、mmap 生命周期 | 失败不能留下半映射或泄漏 |
| 进程 | fork/exec/wait、FD 继承、退出回收、pipe 阻塞 | 错误码和共享偏移不能随实现漂移 |
| 运行时 | ELF/解释器、auxv、TLS、信号、futex、时钟 | Linux ABI 的布局需按架构核对 |
| VFS | 路径、挂载、inode/FD 生命周期、链接、rename、锁顺序 | 无板名/架构 cfg |
| FAT32 / Ext4 | 各自格式与错误；共用 VFS 行为 | Ext4 兼容不能冒充 FAT32 性能 |
| 缓存 | 设备+块号键、引用/pin、逐出、脏块、统计 | 不持全局锁执行慢 I/O，不吞同步错误 |
| 终端与网络 | termios/ioctl、阻塞唤醒；socket/TCP/UDP/loopback | 功能返回必须对应真实行为 |

FS/VFS/缓存应可在 host 用内存盘与故障设备测试，采用 `no_std + alloc`；`cfg(test)` 可用。隔离检查结合依赖图、代码审阅和目标构建，不能只靠字符串搜索。

## 平台接口怎样交接

下表约定交接内容与所有权；类型名作为实现时的统一命名，字段布局由对应专项 SPEC 冻结。不能把未验证的原始固件数据直接当已验证资源使用。

| 交接 | 输入 → 输出 | 所有权与失败状态 |
| --- | --- | --- |
| 板级 → 公共内存 | 原始启动描述 → `BootInfo`：RAM、保留区、CPU、时间源与来源；校验后交付可分配区 | 启动描述使用静态存储或保留的内存；公共内存模块独占可分配页。失败前不修改分配器 |
| 板级 → 驱动 | `DeviceResources`：标识、MMIO、IRQ 连接、时钟/复位、DMA 约束；`DriverServices`：已就绪的映射、分配、时间及所需 IRQ 服务 | 描述不等于资源所有权；成功取得的映射/IRQ/DMA 句柄由驱动持有，失败按 DRV-001 清理 |
| 公共内存 → 架构 | 持有的物理页、映射范围和权限 → 页表操作结果 | 公共内存模块管理页表页、映射和数据页的生命周期；架构实现只在有效借用内操作，不能私自释放页面 |
| 架构 → 进程/调度 | 保存的上下文、异常原因 → 公共异常事件 | 任务对象持有保存的上下文；架构层转换 syscall/缺页/定时等事件，由公共内核决定处理和切换 |
| 驱动 → 公共设备注册表 | 初始化成功的设备 → 统一设备句柄 | 板级启动流程调用公共注册入口，注册表持有设备；IRQ 私有注册不等于设备已经可用 |

DMA 地址的可达范围、映射偏移和缓存一致性由板级/总线资源约束；具体转换、缓存维护或 IOMMU 如需要，由支撑服务实现。驱动只使用服务返回的设备地址。当前不预设必须实现 IOMMU；目标需要但尚不支持时明确拒绝设备接入。

实现 PR 先固定选定接口的 Rust 签名、资源有效期和失败测试；调用方可用假实现先行，提供方必须满足同一契约。三份边界 SPEC 的交叉链接是配套约定，不要求等待其他两层全部完成才开工。

## 提前处理的兼容风险

- **Ext4**：先读取测试与工具镜像的 feature flags，再决定支持范围；支持实际镜像的目录、链接、文件增长与写入语义。FAT32 没有的 Unix 语义不能用假返回补齐。
- **动态程序**：核对目标 ELF、PT_INTERP、依赖库、入口栈和 auxv。工具能输出版本，不代表子进程、链接器和临时文件可用。
- **网络**：锁定的 iperf/netperf 脚本使用 `127.0.0.1`，需真实 TCP/UDP loopback 与进程同步；这不证明物理网卡可用。
- **线程**：`cyclictest -t8` 是 8 个线程，不等于强制 8 核；仍需调度、亲和性/优先级语义、信号和时钟。是否需要 SMP 由具体运行环境再定，不能伪造成功。
- **工具链**：gcc 会启动 cc1、汇编器和链接器；make 还需要 shell、时间戳、依赖与进程退出。用两源文件工程验完整和增量构建。
- **驱动**：QEMU virtio-blk 与 JH7110 SD 分别验收；固件装入内核不代表自有 SD 驱动已完成。

优先复用规范和可审计的 Rust 组件；引入前说明许可证、来源、边界与本队增量。外部 C 测试和用户态 gcc 不改变 Rust 内核约束。
