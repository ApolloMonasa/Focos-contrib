## 四个阶段与三个命令

冻结清单是提交到仓库、人工审查的数据，不增加通用插件或配置语言。下面是拟定接口，**尚不能运行**：

```text
test001 build --image IMAGE --kernel-apk APK --libc glibc --libc musl \
  --group lua --out NEW_BUILD
test001 capture --build NEW_BUILD --firmware OPENSBI --timeout 180 --out NEW_RUN
test001 analyze --run NEW_RUN --out NEW_REPORT --require-pass
test001 analyze --log SERIAL --libc glibc --group lua --out NEW_REPLAY
```

`--run` 与 `--log` 互斥。运行包分析默认涵盖其全部组与 libc；不允许通过只选成功部分获得整次运行的通过。capture 必须显式提供 `--firmware`，具体固件来源、版本与 SHA256 随 C 阶段冻结输入提交审阅；缺失或与冻结哈希不符时在启动前退出 2。外部日志必须显式指定 libc 和组；报告固定 `subject=unknown`、`platform=unknown`，不从日志标记、文件名或调用方描述推断来源。重复/未知组、空选择、非法时限和已存在输出均退出 2。首版不提供自定义 judge、清单、shell 命令、legacy/strict 自动切换和自由平台标签；新增后端需先补 SPEC。

| 阶段 | 输入与输出 | 不承担的职责 |
| --- | --- | --- |
| 冻结 | 版本化清单：源码提交、镜像、APK、OpenSBI 固件、judge 文件哈希、期望项、来源和单位 | 不填写 FocOS 执行成绩 |
| build | 私有输入 → 内核、initramfs、基盘、构建清单 | 不启动 QEMU，不发布通过率 |
| capture | 校验构建包与显式冻结固件 → 原始串口、固件副本、采集清单 | 不加载判分器，不因文本 success 决定通过 |
| analyze | 运行包或外部日志 + 固定判据 → JSON/Markdown 报告 | 不重跑被测程序，不修改运行包 |

每阶段是独立进程；内部模块按这四项职责分开。CLI 只校验参数和调用阶段接口。分析器可重复消费同一运行包；更新判据产生新的报告，并记录新判据身份。

## 文件与发布契约

以下为待实现的包布局，不是当前仓库文件树：

```text
BUILD/  kernel  initramfs.gz  base.img  build.json
RUN/    serial.log  firmware.bin  capture.json
REPORT/ report.json  report.md
```

所有 JSON 有独立 `schema_version: 1`，未知版本、重复键、未知必需语义、NaN/Inf、非法计数均拒绝。清单内文件路径只允许固定相对名称；拒绝绝对路径、`..`、重复成员、符号链接和特殊文件。每个消费阶段先读取同一份清单字节，再校验其所有必需文件的长度与 SHA256。清单自己的 SHA256 由下游记录，不引入自引用哈希。

- `build.json`：冻结清单哈希、构建实现文件集合及哈希、工具版本、输入哈希、组/libc 顺序、内核/initramfs/base.img 哈希及长度、环境适配项。`base.img` 是冻结镜像的完整字节副本，其输出哈希必须等于冻结输入镜像哈希。不得设置“已运行”。相同输入、选择、实现和压缩工具版本应得到相同构建输出；运行时间不写进可复现载荷。
- `capture.json`：每次 capture 调用新生成的 run_id（UUID）、构建清单哈希与副本内容、实际内核/initramfs/基盘哈希、固定 `subject=reference_linux` 与 `platform=qemu_riscv64`、QEMU 路径/二进制哈希/版本、实际 OpenSBI 固件的来源/版本/原路径及 firmware.bin 的 SHA256/长度、实际 argv、开始/结束时间、采集状态、退出码、限额、原始串口哈希及长度、采集实现身份。主机启动生成的 argv 才是采集条件，来宾打印的 build ID 只作一致性检查。
- `report.json`：输入种类与字节哈希、被引用采集清单哈希与 run_id、冻结清单与分析实现/判据文件哈希、subject/platform、所选范围与分母、逐项结果、额外名称、各独立状态、验收阻断原因和计数。报告完成标记为最后写入的 `report.json`；消费者须一并核对其中记录的 `report.md` 哈希。串口保留在运行包；外部日志报告保存来源哈希，不覆盖原文件。

输出路径从可信工作目录逐级以不跟随符号链接的目录句柄访问，独占创建最终目录；后续写入相对此句柄，不重新解析可能被改名的祖先。文件独占新建，不采用先 exists 再覆盖写。文件写入失败只留下未完成目录；清单在所有文件关闭、校验完成后发布。读者仅接受完整清单及其全部文件。首版不承诺掉电事务；重启后仍重新校验，损坏包不能通过。

目录权限为创建者私有。这里防的是正常开发中的并行构建、路径误用、陈旧缓存和半写结果，不承诺抵御拥有同一账户或 root 权限的恶意进程。SHA256 证明内容一致性，不证明发布者身份。

## 输入如何真正固定

构建器把 APK 与镜像复制到自己的暂存区，校验复制后字节与冻结值，再从该副本提取内核、模块和 BusyBox。内存中的提取结果直接交给归档器，不通过共享 `Image/modules` 路径回读。已校验镜像以 `base.img` 纳入构建包，不只保留外部路径；移动完整 BUILD 或删除原始 IMAGE/APK 后仍能采集。模块按该 APK 的依赖图排序；缺模块、环或 release 不符在启动前拒绝。

采集器只从 `--build` 指定包取得内核、initramfs 与 `base.img`，复制到私有运行区并核对哈希；基盘缺失或不匹配在启动前退出 2，不回查 build 时的 `--image` 路径。QEMU 从主机工具链解析、复制并记录身份。显式 `--firmware` 的 OpenSBI 文件先复制到私有运行区的 `firmware.bin`，对副本计算 SHA256 并匹配冻结值，实际 argv 必须使用 `-bios <该副本的绝对路径>`；禁止 `-bios default`、`none` 或隐式搜索主机固件。固件副本随运行包保留，分析时校验其长度、哈希及与采集 argv 的绑定；原始固件路径变化不影响已固定的副本。argv 的被测文件只指向这些私有副本。基盘只读，以独立写时复制层承载测试写入；禁止其他进程复用该层。动态链接器/系统库属于受信主机工具链，记录版本，不声称只凭 QEMU 哈希已冻结完整主机。磁盘空间不足即失败，不退回原路径或硬链接。原始输入在复制期间变化，只有副本哈希仍等于冻结输入时才可继续。

分析器先冻结完整的源码与判据文件集合，再在隔离 Python 搜索路径、空 pycache 的子进程中执行该副本；主脚本、helper、包、数据均显式列入。官方判据只能使用冻结提交中列出的文件，额外同名标准库模块也拒绝。被执行的项目模块均来自副本，报告哈希也从副本生成；不依赖运行前后扫描原目录来证明实际执行身份。整轮历史回放共享一次分析源码快照。

镜像完整复制和哈希只发生在阶段边界，不能随判分组数增长。构建包和运行包容量、串口限额、判据输出限额需在相应实现 PR 给出默认值和超限负例；不为省空间改用共享可写文件。

## 分开事实与验收结论

| 字段 | 允许状态 | 由谁决定 |
| --- | --- | --- |
| origin | `recorded_capture / external_log` | 完整运行包校验或显式日志输入 |
| capture | `EXITED / TIMEOUT / OUTPUT_LIMIT / START_ERROR / NOT_RECORDED`，另存退出码 | 主机采集器 |
| protocol | `VALID / INCOMPLETE / ERROR / NOT_RECORDED`，附阶段错误和脚本退出码 | 协议解析器 |
| section | `COMPLETE / TRUNCATED / ABSENT / INVALID` | 组与 libc 的标记配对 |
| judgment | `PASS / PARTIAL / FAIL / MISSING / JUDGE_ERROR / NOT_RUN` | 固定判据与规范化 |
| acceptance | `PASS / BLOCKED`，附全部原因 | 分析器的单一纯函数 |

`acceptance=PASS` 当且仅当：来源为校验完整的运行包、capture 为 EXITED 且退出码为 0、协议 VALID、每个所选脚本退出 0、范围内所有段 COMPLETE、范围内所有冻结项 judgment 为 PASS、没有判据错误或未知用例。未知项单列且不改分母，但阻断验收，促使重新审查清单。运行包伪造不在本地主机信任模型内；把普通日志附上当前构件或相同 build ID 不改变其 origin。

例如 `capture=EXITED(exit=7)`、`section=TRUNCATED` 与 `judgment=PASS` 可以同时存在，报告保留三项事实，验收为 BLOCKED，原因包含非零退出与截断；不挑一个状态覆盖其他信息。`observed_pass` 统计判据观察值，`accepted_pass` 只有本运行范围验收通过时才等于该范围的 `selected_total`，否则为 0；始终并列显示 origin 和 subject。性能指标保留单位与原值，不合成总分。

外部历史日志仍检查组边界，并可诊断其中协议，但报告的 capture 为 NOT_RECORDED，subject/platform 均为 unknown。运行包分析的 subject/platform 从已校验的采集清单读取，首版仅允许 reference_linux/qemu_riscv64；未知或冲突值作为输入错误拒绝。完整运行包在另一次分析中保持 recorded_capture，表示可追溯的记录，不表示此次重新执行、硬件认证或 FocOS 成绩。

## 范围、汇总与退出码

构建清单中的组列表与 libc 列表的笛卡尔积定义运行范围 `selection`。分析器从同一冻结清单投影出 `(group, libc, case)` 集合，`selected_total` 为其大小；不得以整个清单的 427 项代替本次范围，也不得在分析时删掉失败组。范围外项不生成 MISSING/NOT_RUN；范围内缺组为 NOT_RUN、缺项为 MISSING。运行包中出现范围外组/libc 是协议错误，不能悄悄扩展范围。

按候选旧清单，Lua 每套 libc 为 9 项：示例的双 libc Lua 包分母为 18，全部条件满足时 `accepted_pass=18`、`--require-pass` 退出 0；报告必须标明只覆盖 Lua。冻结全清单则是每套 libc 427 项、双 libc 共 854 项，不能将 18/18 展示成全套通过。

D 阶段另行交付全套汇总：预先固定 22 个 `(group, libc)` 槽位及各自采集清单 SHA256（运行包身份）、报告 SHA256。每个槽位必须满足以下条件，否则全套为 BLOCKED 并列出冲突槽位：

- 对槽位 `(g, c)`，构建包、采集清单内的构建选择、报告范围必须一致，且组列表恰好为 `[g]`、libc 列表恰好为 `[c]`。不能从多组/多 libc 运行中截取子集。双 libc Lua 示例可用于 C 阶段接口验证，不能作为 D 的单槽证据。
- 每槽来自独立一次 capture 调用和一次全新 QEMU 启动。22 个 run_id、采集清单哈希和报告哈希分别不得重复；复制、改名或对同一运行包重新分析不能成为另一槽。报告必须绑定对应采集清单哈希和 run_id，并完整校验运行包；文件路径不同不构成独立运行证据。串口哈希不要求互异，独立运行可能产生相同文本。
- 要求相同冻结清单、被测系统/平台、基盘/APK/工具链、实际固件 SHA256、构建实现、采集实现与环境适配策略，以及同一分析实现和判据快照。采集实现一致性以各 capture.json 中实际执行的完整实现文件集合及逐文件 SHA256 相等为准，不只比较工具名称或版本文本；首版不接受兼容版本集合。固件来源/版本用于追溯，版本文本相同不能替代字节哈希；固件身份缺失或不同同样阻断。缺少身份记录、文件集合不同或任一哈希不同均阻断全套验收。构建选择、构建包哈希、时间及日志允许不同。
- 每个槽位覆盖恰好一次，每个子报告均满足本范围验收，才可报告全套 PASS。缺槽、重复槽或条件不一致均 BLOCKED，不挑选多次尝试中的最佳结果；重测须建立新的完整汇总清单并保留旧清单。分母由各槽位冻结项相加，候选双 libc 清单为 854。

此汇总接口在 D 的实现 PR 中补齐。run_id 由受信采集器在启动前生成并写入最终采集清单，不能由调用方指定；它用于识别重复引用，沿用本地运行记录的信任边界，不构成外部硬件认证。

下表均以参数与包校验通过为前提；输入/参数错误优先退出 2，不执行被测程序。发布失败或工具自身无法完成阶段退出 1，无可消费的完成清单。

| 命令及结果 | 退出码 | 报告/证据语义 |
| --- | --- | --- |
| build 完成并发布构建包 | 0 | 尚未采集 |
| capture 正常退出 0 并发布运行包 | 0 | 尚未判分；来宾协议/脚本仍可能失败 |
| capture 启动失败、超时、超限或非零退出 | 1 | 能完成发布时保留失败运行包供诊断；不表示验收通过 |
| 普通 analyze 完成报告，含 BLOCKED、缺项或 JUDGE_ERROR | 0 | 分析完成，观察结果和验收结论见报告 |
| analyze --require-pass 完成报告且本范围 acceptance=PASS | 0 | 只认可报告明确列出的范围 |
| analyze --require-pass 完成报告且 acceptance=BLOCKED | 1 | 保留报告及全部阻断原因；外部日志必在此列 |

待实现负例须覆盖：缺少固件或复制后哈希不符时不启动 QEMU；替换主机默认固件时已固定显式副本与实际 -bios 参数不变；篡改运行包 firmware.bin 时分析退出 2；22 个槽位的 QEMU 哈希与除私有路径外的参数均相同、仅实际固件哈希不同或缺失时全套 BLOCKED；完整 BUILD 移走原始输入仍可采集；BUILD 缺失/篡改 base.img 时不启动 QEMU；Lua 单组成功无需其他组；选择范围内缺项仍失败；少一个汇总槽位不算全套；把同一双-libc Lua 报告用于两个槽、把同一全套报告用于 22 槽、改名复制同一运行包或重新分析同一次采集均须 BLOCKED；22 份单组单 libc 独立采集且全部条件满足才可全套 PASS；22 个槽位均各自 PASS、其他条件相同但一个槽位采集实现文件集合或哈希不同（或缺失身份）时，全套汇总必须 BLOCKED，并列出冲突槽位和身份差异；同一外部全 PASS 日志的普通分析返回 0、require-pass 返回 1，两个报告均显示 unknown 来源。

## 尝试、判分与真实环境

组标记严格匹配组名/libc，重复、嵌套、错配不得覆盖旧段；EOF 未闭合为 TRUNCATED。官方 judge 崩溃、超时或返回非法 JSON 记 JUDGE_ERROR，不设 fallback。每个期望项的 `all/pass` 为合法整数，PASS 要求 `pass == all > 0`，PARTIAL 要求 `0 < pass < all`；缺项为 MISSING。性能通过仅说明出现约定单位的有限正数。

团队解析器保留每次可识别尝试：开始即登记未完成，结果只消费对应尝试，缺失/失败不能被重试覆盖，重复结果必须可诊断。无法区分的匿名输出不按出现顺序猜测。lmbench 的原脚本 xtrace 仅是输入语法，必须用真实 BusyBox 输出做固定样本；需要新增显式尝试标记时，先在冻结清单中记录 instrumentation 版本和脚本差异，不能声称仍是未修改的原版运行。

模块、挂载、网络、目录/权限、链接和 chroot 预检分别检查真实返回值；失败停止后续组。`ALL_DONE` 只表示循环结束。真实 QEMU 的正常与故障运行必须覆盖整条构建—启动链；伪造命令返回值的 host 测试只验证控制流。

## 实现顺序与验收矩阵
