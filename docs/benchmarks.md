# 怎样做一次可信的性能实验

当前还没有文件系统实测数据。先完成正确的文件读写，再开始优化；这里说明交付方法，不预设加速倍数。

本文的“写穿”指写入继续提交给底层设备；“写回”指先保留在缓存，稍后集中写出。两者都要明确设备真正完成持久化的边界，不能仅凭调用返回就认定断电不丢数据。

## 第一次实验先回答一个问题

“同一组随机读请求，加上块缓存后，真实磁盘读取次数减少了多少，延迟是否下降？”先做这个，不同时叠加目录缓存、写回和向量检索。

1. 冻结能通过功能检查的简单写穿版本 B0，加入物理读写请求计数。
2. 实现固定容量的普通块缓存 B1，继续写穿。
3. 固定板卡、介质、镜像、请求序列和内存预算，对 B0/B1 至少交错跑 7 轮。
4. 保存每轮原始数据，用脚本画延迟和 I/O 次数图，再解释收益或没有收益的原因。

从 [性能任务 #9](https://github.com/MindScrath/Focos/issues/9) 认领。运行脚本尚待实现，不能把计划命令当成现成工具。

## 后续优化怎么比较？

“消融”就是每次只开关一项策略，观察它单独贡献了多少。以普通缓存 B1 为共同对照，再比较目录缓存、写回及其组合；总内存不变。若瓶颈是 FAT 链定位，则单独测试簇链缓存。

| 要验证的策略 | 使用的负载 | 主要看什么 |
| --- | --- | --- |
| 块缓存 | 4 KiB 随机读、热点读和均匀读 | 延迟分布、命中率、物理 I/O 数 |
| 目录缓存 | 多目录反复查找、open、stat | 查找时间、目录块读取、增删后的正确性 |
| 簇链缓存 | 碎片化大文件的随机定位 | FAT 访问数、CPU 时间、内存成本 |
| 写回 | 小块覆盖写、混合读写 | 写放大、脏块峰值、flush 和总完成时间 |

顺序读写作为对照，检查优化有没有损害简单负载。只读检索证明不了写回收益；反复读一个已打开文件，也证明不了目录缓存收益。

## 每次交付数据和图表

保存内核/测试 SHA、硬件与固件、镜像和数据哈希、缓存预算、负载参数、随机种子、预热和清缓存方式、计时边界及每轮数据。冷缓存要说明清的是哪一层。

至少报告中位数、波动范围和样本数；尾延迟每轮建议至少 1000 次请求。图表由脚本生成，标单位和测试条件，能追溯原始数据。计时期间关闭逐请求串口打印，不只选最好的一轮。

写回同时报告“调用返回”“flush”“全部要求的持久化完成”三个时间。成功同步后重启校验，写失败必须上报并保留脏数据。设备没有有效 flush 时，不能声称断电持久化；FAT32 无日志也不意味着任意断电原子性。

## 两块板和向量检索何时加入？

区域赛先做 VisionFive2 的闭环；全国赛再在每块板内部比较自己的基线和优化，展示相对收益。不同 SD/SSD 的绝对速度差不能当成架构差异。

检索必须真的按需从 FAT32 文件读取图节点和向量，不能先把整个索引装进内存。固定数据集、查询、召回率和总内存预算，观察每查询 I/O 与端到端延迟；只读查询先行，在线建图暂缓。

完整参数、实验控制和答辩图表清单见 [实验细则](reference/experiment-protocol.md)。性能回归阈值见 [协作流程](collaboration.md)。
