# FocOS 区域赛与全国赛推进路线

计划基准为 2026-11-04：3 人，均掌握 Rust 基础语法、做过 rCore 实验，每人每周 10–14 小时；VisionFive2 与 2K1000LA 星云板均已到手。先完成可验证的区域赛作品，再扩展全国赛兼容性与跨平台研究。所有里程碑均为团队工程目标，不是获奖或性能承诺。

## 赛事目标与资源分配

本地 2026 年 10 月版章程规定 12 月 24 日报名及作品提交截止，12 月 25–31 日评审、12 月 31 日公布决赛队伍，决赛答辩时间为次年一月中旬、具体另行通知。当前约 7 周，总投入粗估 210–294 人时；预留约 25% 给集成、测试、文档、答辩及故障处理。12 月 20 日作为团队提交目标，最后四天留缓冲。

原理赛参考权重为代码 30%、设计文档 30%、教学价值 10%、工程规范 10%、现场演示与答辩 20%。每周功能交付同时交设计说明、失败用例、串口记录和可复现命令。阶段成果可以凝结为三份教学实验：用户态陷入与调度、FAT32 路径到磁盘块、缓存消融与性能解释。

2026 全国赛已经结束，后续全国赛按下一届准备；2027 年的日期、硬件、测例和评分须等正式发布后锁定。往届规则只作为兼容性预研依据。

## 一条可以用数据证明的主线

研究问题是：在有限内存预算下，如何减少随机小 I/O 的重复取块与元数据访问，并让性能改善在不同硬件上成立？

因果链为：基础功能正确 → 记录真实访问轨迹和瓶颈 → 缓存/写回减少可解释的物理 I/O → 相同源代码在两平台复现 → 用户态磁盘检索的端到端收益。HAL 提供跨平台验证基础，文件系统策略是主要工程贡献，向量检索提供应用证据。

普通 LRU、目录缓存和写回是已有技术，不能单独宣称算法创新。区域赛先完成正确实现和可信比较；全国赛可根据轨迹研究固定总预算下的数据块与 FAT/目录元数据预算分配，和同预算普通 LRU 对照。如果没有稳定改善，就报告适用范围和负结果。

## 区域赛验收边界

| 交付 | 必须达到的可观察行为 |
| --- | --- |
| 启动与设备 | VisionFive2 冷启动，输出版本与硬件信息；真实 UART 输入输出；块设备读写带超时和错误返回 |
| 内存与隔离 | 帧分配/回收、内核堆、Sv39 映射；用户地址检查；错误用户指针不能使整个内核崩溃 |
| 异常、中断、调度 | 定时器驱动两个任务交替运行；异常任务隔离；sleep/yield 行为可观察，保存完整上下文 |
| 用户态与 syscall | 从文件装载静态 ELF，进入用户态，经 syscall 访问文件和控制台，再回收资源；优先匹配所选官方测试的 Linux ABI 子集 |
| FAT32 与 VFS | 挂载、列目录、打开、创建、跨簇读写、关闭、显式同步；重启后校验已同步内容；使用真实磁盘 |
| 演示 | shell 或用户态 runner 串联启动、两个任务、文件操作、历史官方测例和 benchmark；所有声称的能力都能定位到证据 |
| 优化 | 未优化功能基线、至少一项有效优化、相同条件下的消融和成本测量；失败路径通过后才能加入写回 |

单核是区域赛范围，保留多核扩展边界。SMP、完整 POSIX、网络栈、动态链接、复杂 COW 和完整 LTP 放入全国赛待办。向量检索是区域赛可选项；进度不足时优先撤出该项和第二平台完整移植，保留启动、基本功能与实验质量。

FAT32 保留为基础与研究对象。旧国赛的 Ext4 原版镜像不能由 FAT32 直接读取；全国赛若继续采用该要求，需要增加独立 Ext4 兼容后端及相应 VFS 语义，不替换 FAT32，也不能把重打包 FAT32 的测试成绩称作原环境兼容。

## 架构边界与先行契约

未来依赖方向：用户态 shell/测例/检索 → syscall → VFS → FAT32 → 块缓存 → BlockDevice → 板级驱动/HAL；页表、陷入、上下文切换归 arch。当前代码仅建立启动链。

| 边界 | 在实现前写清的契约 | 禁止泄漏到文件系统的内容 |
| --- | --- | --- |
| BlockDevice | 扇区大小与数量、偏移/长度检查、最大传输、对齐、同步读写返回、flush 能力及错误；先用同步接口 | MMIO 地址、设备树解析、DMA 映射与缓存一致性操作 |
| 内存与 arch | 页大小、映射权限语义、TLB 操作、用户内存复制、陷入保存范围与定时接口 | PTE 位编码、CSR、汇编、SBI 或龙芯寄存器 |
| VFS | inode/handle 生命周期、FD 与文件偏移、路径解析、挂载点、错误语义和锁顺序 | `target_arch`、板名、CPU 特性条件编译 |
| FAT32 | BPB 校验、FAT 链边界与环检测、短名/长名、目录增长、截断、空文件、跨簇写、同步范围 | 硬件类型分支与平台定时函数 |
| 缓存 | key 包含设备身份与块号；pin/引用计数、逐出、dirty 状态、错误保留和统计边界 | 直接调用板级驱动、持有全局锁执行慢 I/O |

VFS/FAT32/缓存提取为可 host 测试的 `no_std + alloc` 模块，通过内存盘或故障注入设备测试。`cfg(test)` 可以用于测试；架构或板级 `cfg` 不得出现在 FS/VFS 中。CI 后续同时检查依赖方向、源代码规则和跨目标构建，不能只靠 grep 保证隔离。

区域赛先用简单同步 I/O 和有界轮询完成真实块设备链，再演进中断/DMA。JH7110 的 SD 控制器、时钟、复位、引脚复用、DMA/缓存一致性是独立任务；QEMU virtio-blk 不能证明 SD 驱动已完成。启动固件从 SD 装入内核也不能证明内核具备磁盘驱动。

Linux ABI 要核对 syscall 编号、参数寄存器、返回码、`stat`/`dirent` 布局和 ELF 入口栈。外部官方 C 测试程序是用户态验收工具，不改变内核主要由 Rust 实现的约束。文件名支持按所选测试实际访问路径决定，不能默认 8.3 短名就足够。

A/B/C 是角色而非已分配的人名。三人每周共同参加一次 30 分钟集成演示，平时异步同步阻塞；每人预算包含 review 和文档。C 同样承担真实内核接口实现，避免将能力较弱成员固定为材料整理员。

11 月 15 日如果真实 SD 读写仍受阻，应集中两人排障并撤掉 HNSW 预研；11 月 29 日如果文件闭环未完成，停止新增优化；12 月 6 日如果基础功能仍不稳定，保留一种最可靠优化并投入回归。写回不正确时保持写穿；不能用缺少 flush 的高速结果替代持久化结果。

## 全国赛扩展的验收门

1. 区域赛后先归档已提交版本、评委反馈与缺陷，保持可复现；补齐选定历史 basic 基线。
2. 移植 LoongArch 的启动、页表、异常、中断、定时和上下文切换，接入星云板的真实块设备；同一 FS/VFS 源代码在两板通过同一功能集。QEMU LoongArch 是额外测试环境，不能替代星云板验收。
3. 正式规则发布后锁定赛方分支/SHA/镜像/工具链，补 Ext4 等兼容性差距。按依赖推进 BusyBox、文件系统 benchmark、libc-test 和有针对性的 LTP；信号、futex、mmap、动态加载与网络按实际评分和工时安排。2026 的 final-2026 已包含 glibc/CAgent/BuildStorm，说明冲击全国赛需要单独投入广泛的 Linux 用户态兼容能力；不能仅凭 FAT32 优化和 HNSW 达成这一目标。
4. 双板分别完成同预算缓存消融，报告各自基线上的收益和负结果。平台差异由驱动与 HAL 吸收，FS/VFS 不出现架构条件编译。
5. 运行真实磁盘上的用户态向量检索，固定准确率与内存预算，形成访问轨迹→块请求变化→端到端延迟的解释链。
6. 每次正式提交前，用当届原版镜像及运行入口验证；历史通过记录、重打包记录和正式平台结果分别保存。
