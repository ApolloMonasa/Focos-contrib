# ARCH-001：隔离 CPU 机制与架构 ABI

关联：[Issue #4](https://github.com/MindScrath/Focos/issues/4)、[#5](https://github.com/MindScrath/Focos/issues/5)、[#11](https://github.com/MindScrath/Focos/issues/11) · 状态：草案

## 要做到什么

让公共内核通过统一接口使用 CPU 能力，切换 RISC-V / LoongArch 时复用内存、调度和文件系统逻辑。本规格确定边界；页表、上下文等具体操作须在实现前补充专项 SPEC。

## 行为约定

- **选择**：编译时选择架构实现，对外统一导出；寄存器、页表项、汇编和架构相关 ABI 布局只在架构实现中出现。HAL 提供稳定入口，避免公共模块直接引用 `arch/riscv64` 等具体模块。
- **内存**：公共内存模块拥有物理页和映射生命周期；架构层负责页表操作、权限转换和 TLB 失效。接口必须约定对齐、失败后的映射状态、TLB 完成时机；不支持的权限组合明确报错，不能放宽权限。物理地址、内核虚拟地址和设备 DMA 地址须可区分。
- **执行**：架构层保存/恢复上下文，将异常转换成公共事件；调度、阻塞和退出由公共内核决定。用户上下文、浮点状态、系统调用参数/返回值、TLS 与信号布局须逐架构核对；ELF 机器类型不匹配时拒绝加载。
- **时钟与中断**：统一时间单位和单调性；临界区接口保存并恢复调用前的 CPU 中断状态，不能在退出时无条件开中断。外部中断控制器由驱动实现，板级层提供连接与频率；定时事件交公共调度逻辑处理。
- **接口落地**：每项专项 SPEC 写清签名、调用前提、所有权、并发/unsafe 条件及失败状态。初期单核要求显式标注；增加 SMP 前补跨核 TLB、上下文和同步约定，不能宣称已有多核支持。

## 怎样验收

下列是后续实现门槛，本 PR 未新增运行入口。

| 场景 | 操作或测试入口 | 应看到什么 |
| --- | --- | --- |
| 抽象边界 | 审阅依赖和架构选择；构建各已接入目标 | 公共模块不引用具体架构；不支持的目标明确失败 |
| 页表与隔离 | 各架构 QEMU 专项测试（待实现） | 映射/撤销及权限生效；失败无残留；非法用户访问受控 |
| 上下文与时钟 | 各架构 QEMU 专项测试（待实现） | 任务切换后寄存器正确，定时器持续触发，时间不倒退 |
| 用户 ABI | 各架构最小 ELF、系统调用、TLS/信号测试（待实现） | 参数与返回值正确；错误架构 ELF 被拒绝 |
