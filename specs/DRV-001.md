# DRV-001：用统一接口接入设备

关联：[Issue #2](https://github.com/MindScrath/Focos/issues/2)、[#3](https://github.com/MindScrath/Focos/issues/3)、[#11](https://github.com/MindScrath/Focos/issues/11) · 状态：草案

## 要做到什么

驱动按控制器或协议组织，取得板级资源后提供统一设备接口。先支持 UART 与块设备；中断/总线控制器按实际依赖接入，网卡等接口随任务补充。

## 行为约定

- **装配**：板级层选择设备并传入资源；驱动校验资源和设备标识，初始化成功后才注册。先允许静态装配；VirtIO MMIO 与 PCI 作为不同传输方式适配同一设备逻辑，PCI 仅在目标环境确有需要时接入。
- **资源**：驱动独占控制器状态，经统一服务取得 MMIO 映射、DMA 缓冲区和 IRQ 句柄。映射范围、设备访问属性、对齐和 DMA 可达性须验证；DMA 缓冲区在设备停止访问前不得释放。
- **DMA 与完成**：平台提供缓存一致性能力；架构/HAL 实现必要的缓存维护和屏障，驱动在提交、完成时调用。禁止把普通虚拟地址当设备地址；无法满足可达性/连续性时使用受控中转缓冲区或返回错误。读写成功意味着规定的数据传输已完成，不能只提交请求便返回成功。
- **中断与等待**：驱动处理/确认设备事件，外部中断控制器处理路由与完成；CPU 入口归架构层。初期可轮询，但须设超时；转为中断时先注册处理路径再启用。等待和唤醒使用公共内核服务，不在驱动中另建调度策略。
- **错误与清理**：初始化失败时撤销已注册 IRQ、停止设备访问，再释放资源；若无法确认设备停止，隔离并保留可能仍被 DMA 访问的内存，报告不可恢复错误。具体驱动 SPEC 定义超时、设备错误、恢复范围和并发约束。
- **块设备**：真实驱动实现 [HAL-001](HAL-001.md) 的 `BlockDevice`，保留 `Io` / `Unsupported` 与同步语义。设备块大小不兼容时明确拒绝，或另审转换方案；不得假定所有设备都是 512 字节。公共 FS/VFS/缓存不依赖具体驱动。

## 怎样验收

| 场景 | 操作或测试入口 | 应看到什么 |
| --- | --- | --- |
| 资源与故障 | host 模拟资源/完成事件（待实现） | 非法资源、超时、失败同步可见，资源生命周期正确 |
| 设备基本行为 | 对应 QEMU / 真板专项（待实现） | UART 收发或已知扇区读写正确；与内存盘结果分开记录 |
| 同步与重启 | 真板写入、同步、重启读回（待实现） | 内容一致；不支持同步或失败时不能计通过 |
| 中断与 DMA | 每种实际使用机制的专项（待实现） | 中断可持续处理；数据在完成后可见，无提前复用缓冲区 |

依赖 [ARCH-001](ARCH-001.md)、[PLAT-001](PLAT-001.md)。设备手册、固件版本及复用驱动的提交应在具体 SPEC 锁定；涉及 DMA、IRQ 或持久化需另外两名成员审阅。
