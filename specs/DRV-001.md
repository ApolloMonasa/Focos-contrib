# DRV-001：用统一接口接入设备

关联：[Issue #2](https://github.com/MindScrath/Focos/issues/2)、[#3](https://github.com/MindScrath/Focos/issues/3)、[#11](https://github.com/MindScrath/Focos/issues/11) · 状态：草案

## 要做到什么

驱动按控制器或协议组织，取得板级资源后提供统一设备接口。先支持 UART 与块设备；中断/总线控制器按实际依赖接入，网卡等接口随任务补充。

## 行为约定

- **装配**：板级层选择设备并传入资源；驱动校验资源和设备标识，初始化成功后才发布到公共设备注册表。私有 IRQ 处理器可先安装，安装时保持设备中断源及控制器路由屏蔽。先允许静态装配；VirtIO MMIO 与 PCI 作为不同传输方式适配同一设备逻辑，PCI 仅在目标环境确有需要时接入。
- **资源**：驱动独占控制器状态，经统一服务取得 MMIO 映射、DMA 缓冲区和 IRQ 句柄。映射范围、设备访问属性、对齐和 DMA 可达性须验证；DMA 缓冲区在设备停止访问前不得释放。
- **DMA 与完成**：平台提供缓存一致性能力；架构/HAL 实现必要的缓存维护和屏障，驱动在提交、完成时调用。禁止把普通虚拟地址当设备地址；无法满足可达性/连续性时使用受控中转缓冲区或返回错误。读写成功意味着规定的数据传输已完成，不能只提交请求便返回成功。HAL-001 的缓冲区由调用者借出，任何返回（含错误）前都须结束设备对它的访问；无法保证时须用驱动自有中转缓冲区隔离，或进入终止路径，不能返回后继续 DMA 到调用者内存。
- **中断与等待**：驱动处理/确认设备事件，外部中断控制器处理路由与完成；CPU 入口归架构层。初期可轮询，但须使用已就绪且关中断时仍推进的时间源设超时；不得等待尚未启动的调度器或 IRQ。转为中断时先装处理器，清理事件，再启用路由和设备中断源。等待和唤醒使用公共内核服务，不在驱动中另建调度策略。
- **错误与清理**：初始化失败或运行时超时时，先停止接收新请求、屏蔽设备中断源及控制器路由，再停止 DMA 并等待在途处理器退出，随后注销处理器、撤销映射并释放资源。清理只处理已经取得的资源；共享 IRQ 只能屏蔽本设备来源。若无法确认 DMA 或处理器已停止，隔离设备并保留仍可能被访问的缓冲区、映射和处理状态，报告不可恢复错误。具体驱动 SPEC 定义超时、设备错误、恢复范围和并发约束。
- **块设备**：真实驱动实现 [HAL-001](HAL-001.md) 的 `BlockDevice`，保留 `Io` / `Unsupported` 与同步语义。设备块大小不兼容时明确拒绝，或另审转换方案；不得假定所有设备都是 512 字节。公共 FS/VFS/缓存不依赖具体驱动。

## 第一份实现

#3 先接一个 QEMU 块设备：接收板级设备资源和可用的支撑服务，返回满足 HAL-001 的 `BlockDevice` 或初始化错误。失败对象不发布；对上只暴露块接口，不把 MMIO 指针交给文件系统。具体设备 SPEC 先锁定资源、传输方式、超时上限和测试镜像。

先读固定镜像的已知扇区并校验内容，再在专用测试镜像中验证写入、同步和故障。用可记录调用顺序的 host 假设备验证清理，不能用内存盘代替真实驱动验收。

## 共享接口验收

内存盘、QEMU 块设备和真板 SD 复用同一组 `BlockDevice` 测试逻辑：已知数据读取、长度/块号边界、写后读与 `flush` 返回语义。后端适配只提供设备、专用测试盘/镜像及运行入口，判据沿用 HAL-001；不支持同步仍须验证 `Unsupported`，不能直接跳过。

各后端分别保存结果。故障注入和重启持久化按环境另做专项，不适用项注明原因；共享测试通过不替代真实驱动或真板验收。

共享入口、独立镜像模型和有限观察边界见 [TEST-002](TEST-002.md)。适配者提供至多 8 块的专用测试盘或明确标记范围的测试窗口；完整介质寻址、设备访问顺序与 DMA 生命周期仍按驱动专项验收。

## 怎样验收

| 场景 | 操作或测试入口 | 应看到什么 |
| --- | --- | --- |
| 资源与故障 | host 模拟资源/完成事件（待实现） | 非法资源、超时、失败同步可见，资源生命周期正确 |
| 失败清理 | host 在 IRQ 安装后、DMA 提交后分别注入失败；模拟在途处理器及无法停止 DMA（待实现） | 顺序符合上述约定；处理器退出前不注销/释放状态；DMA 停止前不释放或复用驱动缓冲区；返回时设备不再访问调用者缓冲区；失败设备不再接收请求 |
| 超时可达 | 对应 QEMU / 真板关闭本核中断、阻止设备完成（待实现） | 在具体 SPEC 的时限内报错并清理；不依赖 IRQ 推进超时 |
| 设备基本行为 | 对应 QEMU / 真板专项（待实现） | UART 收发或已知扇区读写正确；与内存盘结果分开记录 |
| 同步与重启 | 真板写入、同步、重启读回（待实现） | 内容一致；不支持同步或失败时不能计通过 |
| 待处理 IRQ 初始化 | host 假控制器与设备在初始化前置入待处理事件，记录处理器安装、事件清理、路由/设备中断源启用顺序；再分别注入安装或清理失败（待实现） | 处理状态就绪并安装处理器 → 清理待处理事件 → 才允许任一解屏蔽；失败时不解屏蔽。启用后新事件能进入已就绪处理器；故意提前解屏蔽的实现必须被测试拒绝 |
| 中断与 DMA | 每种实际使用机制的专项（待实现） | 中断可持续处理；数据在完成后可见，无提前复用缓冲区 |

资源与服务提供方见 [ARCH-001](ARCH-001.md)、[PLAT-001](PLAT-001.md)；先用假服务测试，再接已就绪的真实服务。设备手册、固件版本及复用驱动的提交应在具体 SPEC 锁定；涉及 DMA、IRQ 或持久化需另外两名成员审阅。
