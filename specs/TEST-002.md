# TEST-002：用独立镜像检查块接口

关联：[Issue #34](https://github.com/MindScrath/Focos/issues/34) · 状态：草案，替代 PR #38 的测试设计

## 要做到什么

内存盘、VirtIO 与 SD 使用同一段 `no_std` 检查逻辑，返回后端名、场景、块号和具体差异。接口与错误语义沿用 [HAL-001](HAL-001.md)，设备专项按 [DRV-001](DRV-001.md)。

## 行为约定

- `run_block_contract(backend, device, model, flush)` 接收独占设备、调用方提供的整盘期望字节和明确的同步预期（成功或 `Unsupported`）。例如 4 块镜像对应 4 个 512 字节数组；空盘对应空切片。初始期望来自镜像生成器或独立文件，不能通过被测设备读取后填入。
- 模型由调用方持有，与设备存储分离。只在成功写入后按请求字节更新目标块；任何读取都不能修改模型。先检查容量和全部已知数据，再执行边界组合，然后逐块写入两轮不同内容；两轮分别按字节位置异或 `offset % 255 + 1`、`offset / 255 + 1`，每字节必变且掩码对区分全部 512 个位置，避免全零初始镜像始终只写均匀图样。每次写入后比对整盘，完成后检查实际 `flush` 返回值并再次读回。
- 非法长度 0/511/513 与每个有效块、N、N+1、`u64::MAX` 交叉检查读写；512 字节读取和写入探测三个越界块。空盘走同一流程。参数错误检查返回值；内存盘额外的缓冲区/存储不变保证保留在原测试，不提升为全部驱动的新保证。
- 每次整盘比对用两种不同预填各读取一次，防止未填充或只取反缓冲区的实现碰巧通过。后续正常观察若与模型不符就失败，不从盘面重建或“修复”模型。失败后停止，盘面可能已改动；重跑前重新装载镜像并重建模型。
- 测试盘最多 8 块；超限在访问设备前返回夹具错误。工作区由调用方提供，检查器不分配全盘快照；写入检查为 O(N²)，仅用于极小的专用镜像。真实设备若使用窗口适配器，只能声称窗口内通过，完整寻址范围另测。
- `check_injected_failures` 在转发包装层注入读、写与同步错误，确认调用者收到 `Io`，清除后恢复读写和同步；仅适用于支持同步的非空盘。包装层阻止故障请求到达后端，不把它计为驱动真实错误恢复或失败原子性证据。
- **有限观察边界**：通过只说明这些输入、调用顺序与读回观察符合模型。最后一次读取返回数据后再破坏介质、按调用次数触发、自愈读取、越过测试盘的 DMA 等，不能由同一 `BlockDevice` 的有限读回完整判定。不得声称两遍或三遍读取能证明不存在读取副作用；需独立介质观察、控制器/DMA 专项或重启验证。`flush` 返回成功也不等于断电持久化已验证。

## 怎样验收

| 场景 | 操作或测试入口 | 应看到什么 |
| --- | --- | --- |
| 正常与原行为 | `make test` | 0/1/4/8 块内存盘通过共享入口；原 10 项内存盘断言保留 |
| 判据独立 | 缓存伪读取、丢弃首次/中间块写入、串写未写块的假设备 | 指定场景出现数据差异，不接受任意错误作为负例通过 |
| 边界与能力 | 错误优先级、容量错误、空盘、错误同步返回、故障清除后重试 | 具体返回值和后端/块号可定位，Unsupported 不被跳过 |
| 工程回归 | `make check`、`make mm-smoke` | host 检查和原有 QEMU 启动/内存自检通过；VirtIO/SD 专项待实现 |

SPEC 与实现一并供队友审阅；本 PR 不修改 HAL、ABI、unsafe 或持久化语义，普通 PR 需一名非作者批准。
